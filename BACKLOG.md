## 1. Гейм-фора: линия НЕ в тексте кнопки (mode A) — САМОЕ ЧАСТОЕ
Диагностика (`[диаг betano ctx] ... ⇐ ?`) показала: у голых кэф-кнопок гейм-форы линия **не в предках** —
лежит в СОСЕДЕ / заголовке колонки. Обход вверх её не находит → пул пуст → отказ. За сессию 17:16–17:50
**все 9 отказов** — именно гейм-форы (`AH…геймы`). Значит бо́льшую часть SPREAD-value мы не ставим.
- **Что сделать:** в скрапере `selectLegOutcome` тянуть линию для голой кэф-кнопки из строки/колонки рынка
  (не только предки — соседи/заголовок), собрать `{i,id,text,line}`; `pickOutcome` матчит по этой `line`.
- **Осторожно:** знак (−/+) привязать к правильной кнопке пары — иначе не та сторона (в боте — недопустимо).

## 2. ML по голому кэфу + возможная НЕ ТА сторона
В логе: `ML A|1` → выбрал голую кнопку «2.22» (`how=name`, но имени в тексте нет); `ML B|2` (Luca vs Lorenzo)
→ выбрал «Luca Potenza 2.92» — это **игрок 1**, а нужен был 2. Голый кэф не должен подтверждаться как `name`.
- **Что сделать:** победителя брать ТОЛЬКО по реальному имени или чистому токену стороны («1»/«2»/«X»),
  не по безымянному кэфу; при несовпадении стороны — отказ.

## 3. Персональные тоталы (запрос владельца)
Сейчас фид ОТСЕКАЕТ персональные тоталы («Игрок Games Won Over N»), чтобы они не сталкивались с матчевым
тоталом по ключу `st|kind|param` (иначе de-vig сравнил бы разные рынки → ложный value). Но:
- **(a) простановка:** на странице Betano персональный тотал «Игрок Over N» (БЕЗ «and») пока может совпасть с
  сигналом матчевого тотала. Отсечь в `pickOutcome` по имени игрока в тексте кнопки (комбо с «and» уже режем).
- **(b) фид (опционально):** поддержать персональные тоталы как ОТДЕЛЬНЫЙ рынок — ключ с именем игрока
  (`st|TOTAL|param|player`), чтобы не было коллизии и можно было ловить value и на них.

## 4. verifyPlaced в value-пути (перед боевым режимом!)
Одиночная value-ставка ставит `placed=true` ОПТИМИСТИЧНО сразу после клика (`placeBet`), без подтверждения
приёма БК. В вилочном потоке есть `verifyPlaced` (перечитывает страницу: кнопка постановки исчезла).
- **Что сделать:** после боевого клика в `placeBet` вызвать `verifyPlaced`; не подтвердил → `placed=false` + WARN.

## 5. Верификация очистки купона по betslip-count
`deselectLeg` логирует КЛИК снятия, но не подтверждает, что выбор реально ушёл из купона (нет селектора
betslip-элемента у Betano). См. [[log-verified-not-intended]].
- **Что сделать:** найти селектор строки купона Betano → перечитывать число элементов до/после → лог по факту.
