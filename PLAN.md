# PLAN — прематч: одно плечо вилки на Betano

> Источник правил: `docs/PREMATCH-HANDBOOK.md` (опыт тестовой записи 16–19.11.2026, 71 час, 1 223 пары).
> Там, где этот план расходится с хендбуком, верен хендбук. Очередь правок по лайву — в `BACKLOG.md`.

## Цель

Ставить **одно плечо вилки на Betano** против Pinnacle: **прематч**, **фиксированная сумма**. Лайв-движок и
простановка остаются как есть — прематч добавлен рядом, отдельными модулями.

### Чего нет и почему

- **Модель справедливых цен (раздел 5)** и журнал сигналов по ней (`ev ≥ 5.5%`). Хендбук ссылается на
  `engine/model.py`, которого на этой машине нет. Параметр «разброс общего темпа `v = 0.15`» описан одной строкой —
  без исходника точную форму не восстановить, а писать по догадке значит получить другие числа, чем на проверке.
  Вилкам модель не нужна. Поля `ev / w / l` в журнале пока пустые.
- **Сбор результатов (раздел 10)** и **отчёт (раздел 12)** — следующий этап, после того как пойдёт запись.

## Что перенято из хендбука (чего у нас не было)

   `surebetType` фида, а не по тексту названия рынка.
2. **Противоположная цена** — вилка считается на уровне одного исхода Betano против покрывающей ставки Pinnacle,
   включая синтетику из двух исходов и фору ±0.5. Отсюда появились исход 1X2, двойной шанс и фора 0, которых старый
   движок не сравнивал вовсе.
3. **Сопоставление матчей** с возрастом (U21), женским признаком и резервом, в том числе из названия лиги; порог
   сходства по каждой команде и по сумме; старт ±15 минут.
4. **Перезагрузка сессии** без ложных движений, **заморозка на старте**, **владелец ключа**, **фильтр мигающих
   матчей**, **пропуски записи**.
5. **Журнал вилок**: первое появление, число повторов, максимум, минут до старта, цена закрытия.

## Что добавлено сверх хендбука — другие виды спорта

Хендбук только про футбол. Остальное выведено из дампа фида 19.11.2026 и **записью не проверено**.

- **Период** = `surebetTextId` фида (`/Main/Main/Game`, `/Main/Main/Overtime`, `/Map/Main/1`…): он одинаков у обеих
  контор, поэтому геймы, сеты, овертайм и карты не смешиваются.
- **Победа без ничьей** (`ml`) — отдельное семейство: у Betano в одном сегменте бывают и «Result» (3 исхода), и
  «Winner» (2 исхода) с одинаковыми кодами. Сравнивается только с двухисходным рынком Pinnacle.
- **Фора Betano** (`hc`) против другой стороны той же линии; евро-гандикап с ничьей отсекается.
- **Порядок команд** в US-лигах перевёрнут (101 пара на дампе) — пара помечается `flip`, ключи Pinnacle читаются
  в порядке Betano.
- **Теннис**: время старта у контор расходится на часы, поэтому допуск ±12 часов при полном совпадении имён.
  Рынки по геймам у Pinnacle идут под другим id события — футбольная проверка `meta` к ним не применяется.
- **Двойной шанс**: к П2 / П1 из таблицы хендбука добавлена равносильная фора ∓0.5.

По умолчанию включены: футбол, хоккей, теннис, баскетбол, ам. футбол, CS, Dota. Гандбол, волейбол, дартс, бейсбол
выключены: в Pinnacle-плече фида их сейчас нет, сверить сегменты не с чем.

### Идентификаторы матча в фиде (изучено 22.11.2026)

Схема API поставщика (`/swagger/v1/swagger.json`, описаний полей в ней нет): у игры три поля-идентификатора —
`compareEventId`, `compareName`, `extId`. Методов сравнения событий между конторами в API нет (только
`GetBookmakers`, `GetBookmakerData`, `GetBookmakerSnapshots`, `SubscribeBookmakerData`).

| Поле | Betano | Pinnacle |
|---|---|---|
| `compareEventId` | 0 у всех 2 395 игр | свой номер матча Pinnacle, у всех 1 231 |
| `compareName` | пусто | пусто |
| `extId` | заполнен у 2 205 из 2 395 | пусто |

**`extId` Betano — это номер матча Sportradar** (проверено на 50 играх: команды и время совпали во всех).
Заполненность: футбол 1 378 из 1 439, хоккей 98 из 98, ам. футбол 72 из 73, баскетбол 291 из 314, теннис 49
из 127, киберспорт 0. Общего номера у двух контор нет: числа `extId` не встречаются в данных Pinnacle, и наоборот.

Что даёт номер Sportradar (открытый справочник `stats.fn.sportradar.com/…/gismo/match_info/<id>`):

- **Счёт матча и первого тайма по номеру** — результаты для расчёта без подбора по названиям (хендбук, раздел 10).
- **Точное время старта.** У Betano в фиде оно бывает сдвинуто на 30–120 минут; у Sportradar совпало с Pinnacle во
  всех 9 таких случаях.
- **Страна турнира.** В названиях лиг Betano её нет («Premier League», «First Division»), у Pinnacle есть
  («England - Premier League»). Страна Sportradar совпала со страной Pinnacle в 45 случаях из 45.
- **Каноническое название**, в том числе после переименований: «AFC Ajax II» → «Jong Ajax», «Red Star Belgrade» →
  «Crvena Zvezda», «Albirex Niigata Singapore» → «FC Jurong».

Замер на потерянных парах: из 45 футбольных почти-пар с `extId` 26 склеились ТЕМИ ЖЕ строгими правилами, если
взять название и время из Sportradar. Остальные 19 — разные написания даже у Sportradar и Pinnacle («Aalborg» и
«AaB», «Stade Rennais» и «Rennes», «Olympiacos» и «Olympiakos»); там страна и время совпадают, не сходится одно
название. В теннисе `extId` есть только у 5 из 13 почти-пар, склеились 2.

Ограничения: справочник Sportradar — служебный адрес виджетов статистики, не документированный API: условий
использования и лимитов не знаю, соседний адрес (`lmt.fn.sportradar.com`) ответил отказом. Запрос «все матчи дня»
отдаёт только крупные турниры (1 из 4 проверенных номеров), остальное — по одному запросу на матч.

План по точности, по порядку:

0а. **Сверка матча по номеру Sportradar для пар с вилкой** — ✅ сделана (`lib/prematch/sportradar.cjs`, поле
   `identity` в журнале и в `scan()`: confirmed / mismatch / unknown / noid). Один запрос на матч, с кэшем; запрос
   занимает около 0.35 с (замер: от 0.2 до 2.5 с). На дампе из 9 пар с вилкой 8 подтверждены, у одной нет номера;
   обе пары, помеченные сторожем по ценам как `suspect`, подтвердились.
0. **Использовать номер Sportradar при самой склейке** (ещё не сделано): для игр Betano с `extId` брать из справочника время
   старта, страну и каноническое название как ВТОРОЙ вариант при сопоставлении; запрашивать только по играм без
   пары и кэшировать. Страна + время + одно совпавшее название + сторож по цене — правило для оставшихся
   разночтений. Тем же номером потом собирать результаты.

1. **Закрыть найденные потери**: «Womens» и WTA; синонимы резерва (Jong, Atletico/Atlètic, Promesas, U23, Next Gen,
   II, B) как один признак «вторая команда»; допуск по времени до 2 часов при полном совпадении обоих названий;
   опечатки в один-два символа для длинных слов.
2. **Сторож по цене** — ✅ сделан как ПОМЕТКА, не фильтр (`lib/prematch/guard.cjs`, поле `pairCheck` в журнале
   и в `scan()`): сравнивает цены одних и тех же исходов в двух группах — сила команд и тотал матча; `suspect`,
   если расходятся обе. Футбол на дампе: помечает 84% перепутанных пар с «вилкой» и 2.4% верных пар (в том числе
   2 из 6 пар с настоящей вилкой — поэтому не фильтр: вилка и есть расхождение цен). Вилку из пары `suspect`
   нужно подтверждать отдельно (страна, время и название матча по номеру Sportradar), а не выбрасывать.
   Первоначальная задумка была такой: пара считается подтверждённой, только если вероятность исхода у контор
   сходится; иначе — в спорные и без вилок.
   Замер 22.11 (намеренно перепутанные матчи на дампе): неверная футбольная пара даёт «вилки» в 94% случаев,
   в среднем 10 штук, наибольшая — медиана 20% (у верных пар вилка есть у 0.8% пар, максимум 1.4%). Сверка одной
   только вероятности победы хозяев ловит 82% неверных пар при пороге 5 п.п. и 65% при 10 п.п.; 12% неверных пар
   дают вилку и проходят порог 5 п.п. Значит сторож должен сравнивать несколько рынков сразу (исход, ничья,
   тотал), а не один.
3. **Аудит как инструмент** (`tools/prematch-audit.cjs`): несклеенные с кандидатами, проверка пар, проверка рынков
   по семействам. Запускать на свежих данных после каждой правки правил; цель — ноль неверных пар.
4. **Правила расчёта, а не только названия** — 🟡 сделано со стороны Pinnacle (`lib/prematch/rules.cjs`, там же
   цитаты правил). Официальные правила Pinnacle прочитаны 22.11.2026. Страницы правил Betano с ноутбука закрыты
   блокировкой по стране — их надо открыть в профиле Octo на VDS и свериться.
   - Исключено из сравнения: фора и тотал геймов в парном теннисе и в квалификации ITF (Pinnacle аннулирует их,
     если решающий сет — тай-брейк); вторая половина в баскетболе и ам. футболе (у Pinnacle включает овертайм).
   - Подтверждено: «победа в половине/четверти» без ничьей у обеих контор — возврат при ничьей (у Pinnacle по
     правилу, у Betano по его же ценам); овертайм разведён сегментами фида; футбол — основное время.
   - Не прочитано у Betano: отказ игрока в теннисе. На ставку одним плечом не влияет — при отказе её вернут или
     рассчитают.
5. **Сверка со страницей Betano** — единственная наземная правда: по выборке сигналов открыть событие, сравнить
   название рынка и цену кнопки с ключом и ценой фида. Заодно покажет, насколько свежи цены фида.
6. **Запись на несколько дней** → цена закрытия и результаты → фактическая точность по сыгранным матчам.
7. Остальные виды спорта — тем же аудитом, по одному, после футбола и тенниса.

## Тестовый запуск в приложении (сделано 22.11.2026, не собрано)

Прематч подключён к приложению как отдельный режим; лайв-путь не изменён (252 теста проходят).

- Панель: тумблер «🕒 ПРЕМАТЧ», поле ключа прематч-фида, «Мин. вилка, %», «Сетка оценки, сек».
- Сессия запускается той же кнопкой; при включённом тумблере работает прематч-движок вместо лайв-движка.
- **Простановка — только dry-run**, жёстко: `runValueCycle` вызывается с `live=false`, тумблер «Боевой» на прематч
  не действует. Бот открывает событие, находит кнопку по id из фида, сверяет цену кнопки с ценой фида, открывает
  купон, читает ярлык рынка и чистит купон.
- Что попадает в лог и в `логи/prematch/dryrun-ДАТА.jsonl` по каждой попытке: цена фида и цена кнопки, вилка при
  цене страницы, текст кнопки, ярлык купона, вердикт судьи, итог сверки матча.
- Судьи знают победу, тотал и фору (теннис проверен в лайве). Ничья, фора 0, двойной шанс и тотал команды идут с
  пометкой «рынок судьям не знаком» — dry-run собирает по ним ярлыки купона, по ним допишу судей.
- В коде приложения сам запуск не проверялся (нет Octo на ноутбуке): проверены синтаксис и тесты логики. Первый
  настоящий прогон — на VDS.

Как запустить на VDS: обновить приложение → вписать ключ прематча → включить «ПРЕМАТЧ» и «Простановка» → задать
«Ставка фикс» (в купон вписывается, но не отправляется) → «Запустить сессию». Лайв-клиент на том же ключе не
запускать. Первая загрузка фида — около 170 МБ, до нескольких минут.

## Панель и настройки прематча (0.10.43)

- Панель переделана: окно 1040×780 с изменяемым размером (было 460×560), шапка со статусом и кнопкой запуска,
  разделы слева, одна настройка — одна строка. Показываются только настройки включённого режима (лайв или прематч).

- Раздел «Спорт и исходы»: галочки видов спорта, исходов (победа, ничья, двойной шанс, фора 0, фора, тотал, тотал
  команды или игрока) и отрезка (весь матч / части). Настройки `betSports`, `betOutcomes`, `betFull`, `betParts`;
  пустой список — включено всё. В лайве выключенные виды спорта в простановку не идут, исходы сводятся к
  `valuePlaceKinds`.
- Убраны из панели: «Только настоящие вилки», «Только победа», «Сетка оценки».
- Вилки пересчитываются после каждого опроса фида (сетки нет), каждая контора опрашивается раз в ~2 секунды
  (было 10). Пауза 5 секунд между полными загрузками держится в клиенте фида.
- Вилка в прематче задаётся «от и до» (`prematchMinArb`, `prematchMaxArb`; 0 — без потолка).

## Следующие шаги

0. **По итогам тестового запуска**: по `dryrun-*.jsonl` дописать судей под футбольные и прочие рынки; посчитать,
   как часто вилка из фида подтверждается ценой кнопки.
1. **Подключить прематч-движок к приложению** — ✅ сделано, см. выше. Исходная формулировка: — режим «Прематч» в панели, пока без простановки: показывать вилки и
   писать журнал. Ключ прематча и ключ лайва — разные; один ключ опрашивает одна программа.
2. **Простановка одного плеча, сначала dry-run.** Связка та же: `selId` из фида → кнопка на странице Betano. Судьи
   сейчас знают теннисные рынки; для футбола нужны ярлыки купона «Match Result», «Draw No Bet», «Double Chance»,
   «Over/Under» — их надо снять с реальных прематч-страниц («Снять купон»), а не угадывать.
3. **Проверка по странице перед кликом**: вилка должна оставаться при цене, которую показывает кнопка Betano.
   Хендбук: Betano отстаёт от Pinnacle на 4–7 минут, после появления вилки режет цену в 9 случаях из 10.
4. **Фильтры ставки — настройками, не в коде** (хендбук 7.2, 13): размер вилки, семейство, цена. На записи плюс
   дали исходы и цены до 2.0, вилки от 4%; тоталы и тоталы команд плюса не дали; цены от 5 исключать.
   Ни одна цифра записи статистически не отличалась от нуля — нужно 400–500 матчей с результатом.
5. **Результаты и отчёт**: сбор счетов (Flashscore), расчёт, срезы из раздела 14.
6. **Модель** — когда появится `engine/model.py`.

## Открытые вопросы

- Сетка оценки. В хендбуке 2 минуты — так велась запись. Для ставок это задержка до 2 минут при отставании Betano
  в 4–7 минут. Движок принимает любую сетку (`gridMs`); какую брать для боевого — решить по записи.
- Свежесть прематч-цен Betano в фиде не подтверждена: у 1 291 игры из 2 395 метка парса старше 10 часов. Вопрос к
  поставщику из хендбука (существовали ли «мигающие» цены на сайте) тоже открыт.
- Допуск ±12 часов для тенниса выбран по дампу; при ±15 минутах терялась большая часть теннисных пар.
- Баскетбол, «победа в половине/четверти» (`ml`): вилка верна, только если при ничьей в отрезке обе конторы
  возвращают ставку. Правила расчёта Betano для «1st Half - Winner» не проверены — до проверки такие вилки
  считать сомнительными (на прогоне одна: 2.61%).
- Вилки на первой половине в баскетболе малых лиг держались весь прогон без движения Betano — либо Betano не
  следит за линией, либо цена в фиде устарела. Различить можно только по странице.
